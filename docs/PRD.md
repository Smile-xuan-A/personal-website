# 个人网站 · 产品需求文档（PRD）

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 个人作品集网站（Personal Portfolio） |
| 文档版本 | v1.0 |
| 日期 | 2026-10-29 |
| 形态 | 动态网站（前台展示 + 站主自用后台） |
| 参考 | [developer-portfolios](https://github.com/emmabostian/developer-portfolios) 中收录的个人站案例 |

## 1. 背景与目标

### 1.1 背景

个人主页是设计师 / 开发者的"线上名片"。静态页面每次改内容都要改代码、重新部署，维护成本高。本项目希望把「展示」与「编辑」分离：访客看到的是完整作品集，站主在后台改字、加项目、发文章，前台即时生效。

### 1.2 目标

1. 一页看懂：访客在 30 秒内了解"你是谁、会什么、做过什么、写过什么"。
2. 可持续更新：技能、项目、博客内容都通过后台维护，不需要改代码。
3. 有设计感：暗色科技风，体现设计能力与技术气质，而非套模板。
4. 单一使用者：后台仅站主本人使用，不引入多用户与权限体系。

### 1.3 非目标（本期不做）

- 访客注册、账号体系、评论、点赞（后台口令登录仅服务站主一人，不构成用户系统）
- 多管理员与角色权限
- 图片上传与对象存储（项目封面使用外链 URL；仅头像支持后台直传并存入数据库）
- 访问统计、SEO 后台、多语言切换
- 独立部署运维平台

## 2. 用户与场景

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 访客（招聘方 / 同行 / 客户） | 通过链接进入网站，快速评估能力 | 快速浏览项目与文章，能联系到本人 |
| 站主（唯一后台使用者） | 网站所有者，设计与开发本人 | 不改代码即可更新介绍、技能、项目与文章 |

### 2.1 关键场景

1. 招聘方打开首页 → 看简介和技能 → 点进 2 个项目 → 打开 GitHub / 线上地址。
2. 同行从博客文章分享链接进入 → 读完文章 → 返回首页看作者。
3. 站主完成一个新项目 → 进入后台 → 新建项目、填写技术栈与链接 → 勾选"首页精选" → 前台立即可见。
4. 站主修改个人简介或技能熟练度 → 保存 → 刷新首页即生效。

## 3. 信息架构

```
/                     首页（个人介绍 + 精选技能 + 精选项目 + 最新文章）
/projects             项目列表（全部项目，可按技术栈筛选）
/projects/[id]        项目详情（可选，展示完整描述）
/blog                 博客列表（已发布文章，按时间倒序）
/blog/[slug]          文章详情（Markdown 渲染）
/about                关于页（完整经历、联系方式）
/login                后台登录（口令校验，未登录访问 /admin 时跳转至此）
/admin                后台 · 基本信息（需登录）
/admin/skills         后台 · 技能管理
/admin/projects       后台 · 项目列表 / 新建
/admin/projects/[id]  后台 · 编辑项目
/admin/posts          后台 · 文章列表 / 新建
/admin/posts/[id]     后台 · 编辑文章
```

## 4. 功能需求

优先级：P0 = 本期必须；P1 = 本期应做；P2 = 后续可做。

### FR-01 个人介绍（P0）

- 首页顶部展示：姓名、职位 / 身份、一句话标语、头像、所在城市、可合作状态。
- 展示联系方式：邮箱、微信、QQ、电话（未填写的不显示；电话可点击拨号，微信 / QQ 仅展示号码）。
- 头像可手动填写图片地址，也可在后台直接上传图片（JPG / PNG / WebP / GIF，≤ 2MB）；有上传图时优先使用上传图。
- 首页展示精简版个人简介，`/about` 展示完整简介。
- 数据全部来自后台「基本信息」，不写死在页面里。

**验收**：修改后台姓名后刷新首页，标题与导航同步更新；清空某个社交链接后对应入口消失；后台上传新头像后首页与关于页同步更新，移除上传图后回落到头像地址。

### FR-02 技能展示（P0）

- 按分类分组展示（如 设计 / 前端 / 工具）。
- 每个技能显示名称与熟练度（0–100，前台用进度条 + 数值呈现）。
- 支持排序字段，前台按分类与排序值稳定展示。

**验收**：新增技能后出现在对应分类；修改熟练度后进度条比例变化。

### FR-03 项目展示（P0）

- 项目卡片展示：序号、标题、一句话简介、技术标签、年份、仓库 / 演示链接。
- 首页仅展示 `featured = true` 的项目（最多 4 个），`/projects` 展示全部。
- 无链接的按钮不渲染；技术标签为空时不显示标签行。

**验收**：后台勾选"首页精选"后首页出现该项目；取消后消失。

### FR-04 博客（P0）

- 文章列表按发布时间倒序，展示标题、摘要、日期、标签、预计阅读时长。
- 文章详情使用 Markdown 渲染（标题、列表、代码块、引用、链接）。
- 支持草稿 / 发布两种状态；草稿不出现在前台。
- 文章 slug 唯一，用于 URL；重复时保存失败并提示。

**验收**：新建草稿文章前台不可见；发布后可通过 `/blog/[slug]` 访问；修改标题不影响已有 slug。

### FR-05 后台编辑（P0）

- **仅站主本人可访问**：`/admin` 及其全部子页面必须先通过口令登录，未登录一律跳转 `/login`。
- 口令由环境变量 `ADMIN_PASSWORD` 配置，不写入数据库、不写入代码；登录成功后写入 HttpOnly 会话 Cookie（有效期 7 天）。
- 支持「退出登录」，主动清除会话。
- 会话失效或未登录时直接调用写入接口，必须被拒绝，不得修改任何数据。
- 同一来源连续 5 次口令错误后锁定 10 分钟，降低公网暴力猜测风险。
- 四个模块：基本信息、技能、项目、文章，均支持增 / 删 / 改。
- 保存使用表单提交（Server Action），成功后停留在当前页并给出成功提示。
- 删除操作需要二次确认。
- 表单做基础校验：必填项为空、slug 重复、数字越界时给出错误提示，不写入数据库。

**验收**：
- 未登录访问 `/admin`、`/admin/skills`、`/admin/posts` 均跳转登录页；
- 错误口令提示「口令不正确」且不进入后台；正确口令进入后台；
- 退出登录后再次访问 `/admin` 重新要求登录；
- 断网或数据库异常时不出现白屏，页面给出错误提示。

### FR-06 视觉与交互（P1）

- 暗色科技风：近黑背景、低对比网格、单一强调色、等宽字体点缀。
- 全站响应式：≥1024 三栏信息密度、768 两栏、≤640 单栏。
- 动效克制：仅入场淡入与悬停位移，支持 `prefers-reduced-motion` 关闭。
- 键盘可达：所有链接 / 按钮有可见焦点态。

**验收**：在 375 / 768 / 1440 宽度下无横向滚动、无文字溢出。

### FR-07 内容为空时的表现（P1）

- 无项目 / 无文章时展示空状态文案，而不是空白区块。
- 头像为空时使用姓名首字母占位。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首页首屏 JS ≤ 150KB（gzip）；无第三方 UI 库；字体使用系统字体栈 |
| 可访问性 | 正文对比度 ≥ 4.5:1；交互元素有 `:focus-visible`；图片有 `alt` |
| 响应式 | 320px–1920px 可用；断点 640 / 900 / 1200 |
| SEO | 每页有 title / description；文章页输出摘要；提供 `sitemap.xml` 与 `robots.txt` |
| 数据 | SQLite 单文件；首次启动自动建表并写入示例数据 |
| 安全 | 后台口令登录（`ADMIN_PASSWORD` + 签名会话 Cookie，HttpOnly / SameSite=Lax / 生产环境 Secure）；写接口逐个校验会话；`/admin`、`/login` 不被搜索引擎收录；公网部署仍建议叠加 HTTPS |
| 兼容 | 最新版 Chrome / Edge / Safari / Firefox |

## 6. 数据对象

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| Profile | name, title, tagline, bio, avatar, location, email, wechat, qq, phone, available | 全站唯一一条 |
| Skill | name, category, level(0–100), sortOrder | 按分类分组 |
| Project | title, summary, description, tech[], cover, repoUrl, demoUrl, year, featured, sortOrder | `tech` 存逗号分隔字符串 |
| Post | title, slug, excerpt, content(Markdown), tags[], published, publishedAt | 草稿不对外 |

## 7. 界面与内容要求

### 7.1 首页区块顺序

1. 顶部导航（Logo / 首页 / 项目 / 博客 / 关于 / 后台入口）
2. Hero：状态徽标 + 姓名 + 标语 + 简介摘要 + 社交按钮 + 右侧终端风格信息卡
3. 数据条：项目数、文章数、技能数（由数据库实时统计）
4. 技能：按分类分组
5. 精选项目：卡片网格
6. 最新文章：列表
7. 页脚：版权 + 后台入口

### 7.2 文案基调

- 第一人称、短句、具体，不写"致力于打造卓越体验"这类空话。
- 技术标签统一小写或统一首字母大写，全站一致。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 后台口令泄露或被暴力猜测 | 内容被篡改 | 口令仅存于服务端环境变量、不入库不入代码；会话 Cookie 为 HttpOnly + 签名；连续 5 次失败锁定 10 分钟；公网部署使用 HTTPS |
| 环境变量未配置 | 无法登录后台 | 登录页提示「服务器未配置」；部署检查清单要求配置 `ADMIN_PASSWORD`、`AUTH_SECRET` |
| SQLite 单文件并发写 | 高并发下锁等待 | 本站为单用户写入，读多写少，可接受 |
| Markdown 注入 HTML | XSS | 仅站主可写；渲染时禁用原始 HTML |
| 示例数据被误当真实内容 | 上线前忘改 | 后台首屏提示"示例数据，请替换" |
